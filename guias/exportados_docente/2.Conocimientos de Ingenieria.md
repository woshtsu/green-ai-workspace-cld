**2.Conocimientos de Ingenieria**

Revisando la documentación oficial vigente de ICACIT, hay una precisión importante: **para el ciclo 2026 el atributo de egreso de Ingeniería es AG-I07: Conocimientos de Ingeniería**. ICACIT lo formula como la capacidad de **aplicar conocimientos de matemáticas, ciencias naturales, computación y conocimientos fundamentales y especializados de ingeniería para desarrollar soluciones a problemas complejos de ingeniería**. ([webicacit.com](https://webicacit.com/archivos/2027_ICACIT_Criterios.pdf?utm_source=chatgpt.com))

Para un **proyecto de Ingeniería de Sistemas e Informática basado en TI**, no recomendaría que el estudiante coloque simplemente un capítulo denominado "Marco teórico". Para evidenciar AG-I07, debe demostrarse **qué conocimientos de ingeniería se necesitan, cómo se seleccionan, cómo se aplican y cómo se comprueba que fueron adecuados para desarrollar la solución**.

**1. Secuencia recomendada de secciones para AG-I07**

La estructura que recomiendo para un proyecto TIC es:

| **N.º** | **Sección** | **Pregunta que debe responder** | **Evidencia** |
| --- | --- | --- | --- |
| **1** | **Definición del problema de ingeniería** | ¿Qué problema complejo debe resolverse? | Problema, contexto y restricciones |
| **2** | **Requerimientos y necesidades de ingeniería** | ¿Qué debe lograr la solución? | Requerimientos funcionales/no funcionales |
| **3** | **Fundamentos matemáticos y científicos** | ¿Qué conocimientos matemáticos/científicos son necesarios? | Modelos, fórmulas, estadística, probabilidad |
| **4** | **Conocimientos de computación** | ¿Qué conocimientos de computación sustentan la solución? | Algoritmos, estructuras de datos, BD, IA, ML, etc. |
| **5** | **Conocimientos fundamentales de ingeniería** | ¿Qué principios de ingeniería intervienen? | Ingeniería de software, sistemas, procesos, calidad |
| **6** | **Conocimientos especializados** | ¿Qué conocimientos especializados requiere el dominio? | Cloud, IA, IoT, ciberseguridad, GIS, etc. |
| **7** | **Selección y justificación de tecnologías** | ¿Por qué se seleccionan determinadas tecnologías? | Matriz de evaluación tecnológica |
| **8** | **Aplicación de los conocimientos al diseño** | ¿Cómo se aplican esos conocimientos en la solución? | Arquitectura, modelos, algoritmos, diseño |
| **9** | **Integración de conocimientos** | ¿Cómo interactúan los diferentes conocimientos? | Arquitectura integral, trazabilidad |
| **10** | **Validación de la aplicación de conocimientos** | ¿La aplicación de esos conocimientos produce una solución adecuada? | Pruebas, métricas, experimentos |
| **11** | **Conclusiones de conocimientos de ingeniería** | ¿Qué conocimientos fueron determinantes y qué se logró con ellos? | Conclusiones sustentadas |

**2. La secuencia lógica que debería observar el proyecto**

La evidencia de AG-I07 debería seguir esta cadena:

**Problema complejo**

↓

**Necesidades y restricciones**

↓

**Conocimientos requeridos**

↓

**Selección de conocimientos**

↓

**Aplicación al diseño**

↓

**Integración**

↓

**Implementación**

↓

**Validación**

↓

**Conclusiones**

Esto es mucho más sólido que presentar:

"Tecnologías utilizadas: Java, MySQL, React, Python..."

Una lista de tecnologías **no demuestra conocimientos de ingeniería**.

Lo que debe demostrarse es:

**Problema → conocimiento requerido → aplicación → decisión de ingeniería → resultado.**

**3. ¿Qué debe contener cada sección?**

**3.1 Definición del problema de ingeniería**

Debe existir conexión directa con el **Análisis de Problemas (AG-I08)**.

Por ejemplo:

El problema consiste en predecir oportunamente el riesgo de abandono de estudiantes utilizando información histórica académica y socioeducativa.

Aquí se define la necesidad de conocimientos de:

* estadística;
* aprendizaje automático;
* bases de datos;
* ingeniería de software;
* arquitectura de software;
* visualización de información.

**3.2 Requerimientos y necesidades de ingeniería**

Determinar qué necesita resolver la ingeniería.

Ejemplo:

| **Necesidad** | **Requerimiento** |
| --- | --- |
| Predecir riesgo | Modelo ML |
| Procesar información | Pipeline de datos |
| Integrar sistemas | API |
| Consultar resultados | Dashboard |
| Proteger información | Seguridad |
| Escalar usuarios | Arquitectura escalable |

**4. Fundamentos matemáticos y científicos**

Esta sección es **muy importante para demostrar AG-I07**.

No basta con decir:

"Se utilizará Machine Learning."

Debe explicarse qué conocimiento matemático sustenta el modelo.

Por ejemplo:

**Para Machine Learning**

* estadística descriptiva;
* probabilidad;
* distribución de datos;
* correlación;
* regresión;
* funciones de pérdida;
* métricas de clasificación;
* matriz de confusión.

Ejemplo:

Para evaluar el modelo de clasificación se utilizarán precisión, recall, F1-score y matriz de confusión, debido a que el problema presenta dos clases: estudiante en riesgo y estudiante sin riesgo.

Aquí ya existe **aplicación de conocimiento**, no solamente descripción.

**5. Conocimientos de computación**

Para un proyecto de Sistemas e Informática recomiendo dividir esta sección en subáreas:

**5.1 Algoritmos y estructuras de datos**

**5.2 Bases de datos**

**5.3 Ingeniería de software**

**5.4 Arquitectura de software**

**5.5 Inteligencia artificial / Machine Learning**

**5.6 Redes y comunicaciones**

**5.7 Seguridad informática**

**5.8 Sistemas distribuidos / Cloud**

**5.9 Interacción humano-computador**

**No todos deben aparecer en todos los proyectos.** Deben seleccionarse según el problema.

**6. Conocimientos fundamentales de ingeniería**

Aquí debe demostrarse el conocimiento propio de la **Ingeniería de Sistemas/Software**.

Por ejemplo:

* ingeniería de requisitos;
* modelamiento;
* diseño de software;
* arquitectura;
* patrones;
* calidad de software;
* gestión de configuración;
* pruebas;
* integración;
* mantenimiento;
* gestión de riesgos.

Ejemplo:

Debido a la necesidad de desacoplar la lógica de negocio de los mecanismos de persistencia y de las interfaces externas, se adopta arquitectura hexagonal.

Eso evidencia una **decisión sustentada en conocimiento de ingeniería**.

**7. Conocimientos especializados**

Aquí se incorporan los conocimientos específicos del proyecto.

Por ejemplo:

**Proyecto de agricultura**

* IoT;
* sensores;
* agricultura de precisión;
* Machine Learning;
* procesamiento de imágenes.

**Proyecto de salud**

* interoperabilidad;
* HL7/FHIR;
* procesamiento de señales;
* IA;
* seguridad de datos.

**Proyecto municipal**

* gobierno digital;
* interoperabilidad;
* gestión documental;
* seguridad;
* procesamiento de lenguaje natural.

**Proyecto de incendios forestales**

* Edge AI;
* visión computacional;
* sensores;
* GIS;
* redes IoT.

**8. Selección y justificación de tecnologías**

Esta sección es especialmente recomendable para un proyecto capstone.

En lugar de:

"Se utilizará Python porque es popular."

hacer:

| **Criterio** | **Python** | **Java** | **Node.js** |
| --- | --- | --- | --- |
| ML/IA | 5 | 3 | 3 |
| Bibliotecas | 5 | 4 | 4 |
| Integración | 5 | 4 | 5 |
| Productividad | 5 | 3 | 5 |
| Comunidad | 5 | 5 | 5 |
| **Puntaje** | **25** | **19** | **22** |

Luego:

Se selecciona Python debido a que obtiene el mayor puntaje y presenta ventajas particularmente relevantes para la implementación del componente de Machine Learning.

Esto convierte la selección tecnológica en una **decisión de ingeniería**.

**9. Aplicación de conocimientos al diseño**

Aquí debe aparecer la evidencia principal.

Por ejemplo:

**Conocimiento → aplicación**

| **Conocimiento** | **Aplicación en el proyecto** |
| --- | --- |
| Estadística | Preparación y análisis de datos |
| Machine Learning | Modelo predictivo |
| Ingeniería de software | Historias de usuario y requisitos |
| Arquitectura | Arquitectura hexagonal |
| Bases de datos | Modelo relacional |
| Seguridad | Autenticación/autorización |
| Cloud | Despliegue escalable |
| UX | Diseño de interfaz |

Esta tabla genera una excelente **trazabilidad de AG-I07**.

**11. Validación**

Debe responder:

**¿Cómo sé que los conocimientos aplicados fueron adecuados?**

Ejemplos:

**Software**

* pruebas unitarias;
* pruebas de integración;
* pruebas de rendimiento;
* cobertura.

**Machine Learning**

* Accuracy;
* Precision;
* Recall;
* F1-score;
* ROC-AUC.

**Arquitectura**

* acoplamiento;
* cohesión;
* complejidad;
* disponibilidad;
* rendimiento.

**Usabilidad**

* SUS;
* tasa de éxito;
* tiempo de tarea;
* satisfacción.

La validación permite cerrar la cadena:

**Conocimiento → aplicación → resultado → evidencia.**

**La trazabilidad que exigiría al estudiante**

| **AG-I07** | **Evidencia mínima** |
| --- | --- |
| **Aplica** | No solo define conceptos; los utiliza |
| **Matemáticas** | Modelos, estadística, métricas, etc. |
| **Ciencias naturales** | Solo cuando sean pertinentes al dominio |
| **Computación** | Algoritmos, BD, IA, arquitectura, etc. |
| **Ingeniería fundamental** | Requisitos, diseño, calidad, procesos |
| **Ingeniería especializada** | Conocimiento específico del proyecto |
| **Desarrolla soluciones** | Evidencia de implementación/diseño |
| **Problema complejo** | Múltiples restricciones y componentes |
| **Trazabilidad** | Problema → conocimiento → decisión → solución → validación |

**Punto clave para la evaluación ICACIT:** AG-I07 no debería evaluarse por la cantidad de conceptos teóricos que el estudiante presenta, sino por la **capacidad demostrada para aplicar conocimientos de matemáticas, ciencias naturales, computación y fundamentos/especialidades de ingeniería en el desarrollo de una solución a un problema complejo**. Esa es la diferencia entre un "marco teórico" y una verdadera **evidencia de conocimientos de ingeniería**.
