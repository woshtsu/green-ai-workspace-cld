**1. OBJETIVOS DE LA PRÁCTICA**

Al finalizar la sesión de laboratorio, el equipo de estudiantes será capaz de:

1. **Demostrar el despliegue automatizado o continuo** de la solución de software en un entorno de calidad en la nube (Staging/QA) directamente desde la estructura de carpetas del repositorio GitHub basada en **Arquitectura Hexagonal**.
2. **Demostrar la puesta a punto e integración** de los componentes del software, la base de datos gestionada en la nube y los servicios externos (incluyendo módulos o APIs de Inteligencia Artificial).
3. **Validar las pruebas funcionales end-to-end** del PMV1 y PMV2 mediante capturas de pantalla con datos reales de prueba, fundamentadas en los **Criterios de Aceptación** (*Given / When / Then*) de las Historias de Usuario.
4. **Elaborar y presentar un Informe Integrado de Resultados** que consolide la evidencia técnica, la arquitectura desplegada y las métricas de prueba obtenidas.

**3. PRE-REQUISITOS Y RECURSOS REQUERIDOS**

* **Repositorio en GitHub:** Código fuente organizado bajo Arquitectura Hexagonal con carpetas independientes (/domain, /application, /adapters, /infrastructure) y ramas de trabajo activas.
* **Servicios Cloud Proveedores (No Localhost):** Cuentas activas en servicios PaaS/SaaS/IaaS (ej. Render, Vercel, Railway, AWS, GCP, Azure, Supabase o MongoDB Atlas).
* **Herramientas de Soporte:** Postman / Insomnia para pruebas de API, cliente de base de datos remoto (ej. DBeaver, pgAdmin) y entorno de ejecución para IA.
* **Backlog de Historias de Usuario:** Historias del PMV1 y PMV2 con Criterios de Aceptación especificados en formato *Given / When / Then*.

**4. ORGANIZACIÓN DE ACTIVIDADES**

**ACTIVIDAD 1: DESPLIEGUE EN ENTORNO DE CALIDAD/STAGING EN LA NUBE (NO LOCALHOST)**

* **Objetivo:** Garantizar la publicación automatizada de la solución desde el repositorio GitHub hacia la infraestructura nube, verificando el desacoplamiento arquitectónico.
* **Responsables:** Architect & System Designer (ARQ) y QA & DevOps Engineer (QA).

**Pasos a ejecutar:**

1. **Configuración de CI/CD / Vinculación:** Conectar el repositorio de GitHub con la plataforma de alojamiento en la nube (ej. Vercel para Frontend, Render/Railway para Backend, o GitHub Actions).
2. **Despliegue por Capas (Arquitectura Hexagonal):**
   * Desplegar el núcleo de la aplicación verificando que el paquete del Dominio (/domain) no posea dependencias a servicios locales ni frameworks.
   * Configurar los Adaptadores de Entrada (*Controllers REST/HTTP*) y de Salida (*Persistencia, Servicios externos de IA*) apuntando a las variables de entorno de Staging.
3. **Verificación de URLs Públicas:** Obtener y registrar la URL pública del Frontend desplegado y el endpoint base HTTPS del Backend.
   * *Restricción:* Queda estrictamente prohibido el uso de direcciones localhost, 127.0.0.1 o túneles temporales de desarrollo local (ej. ngrok).

**ACTIVIDAD 2: PUESTA A PUNTO DEL SOFTWARE, BASE DE DATOS Y SERVICIOS EXTERNOS/IA**

* **Objetivo:** Configurar la persistencia de datos remota, las variables de entorno y la comunicación funcional con el servicio de Inteligencia Artificial.
* **Responsables:** Lead Backend & AI Engineer (AIE) y Lead Frontend & Integration Engineer (DEV).

**Pasos a ejecutar:**

1. **Provisionamiento de Base de Datos Remota:**
   * Crear e inicializar la instancia de base de datos en la nube (ej. PostgreSQL en Render/Supabase o MongoDB Atlas).
   * Ejecutar los scripts de migración DDL y carga de datos iniciales (*seeding*) para permitir las pruebas.
2. **Configuración de Variables de Entorno y Secretos:**
   * Cargar las claves secretas (API Keys de IA, cadenas de conexión a la BD, tokens JWT) en el panel de administración del proveedor Cloud.
3. **Puesta a Punto del Módulo de IA y Servicios Externos:**
   * Verificar la conectividad del modelo de IA (desplegado como microservicio o consumido vía API externa) con el backend.
   * Validar la latencia de respuesta de las peticiones de inferencia/predicción.

**ACTIVIDAD 3: EJECUCIÓN DE PRUEBAS FUNCIONALES Y CAPTURA DE EVIDENCIAS (PMV1 Y PMV2)**

* **Objetivo:** Validar cuantitativamente el cumplimiento de las Historias de Usuario priorizadas para el PMV1 y PMV2 en la interfaz nube funcional.
* **Responsables:** QA & DevOps Engineer (QA), Lead Frontend (DEV) y Project Manager (PM).

**Pasos a ejecutar:**

1. **Selección de Escenarios de Prueba:** Tomar las Historias de Usuario del PMV1 y PMV2 y sus Criterios de Aceptación (*Given / When / Then*).
2. **Ejecución en el Entorno Cloud:**
   * Ingresar a la URL pública desplegada y realizar las operaciones de flujo continuo (ej. registro, procesamiento de datos, generación de predicción por IA).
3. **Registro de Evidencias Fotográficas/Capturas con Datos:**
   * Capturar pantallas completas de la interfaz donde se observe claramente: la URL pública en la barra de direcciones, los datos de entrada ingresados y el resultado producido por el sistema/IA.
   * Capturar la evidencia de actualización en la Base de Datos remota y los registros de respuesta (*logs/payloads*) del servidor.
